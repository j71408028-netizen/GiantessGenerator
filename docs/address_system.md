# 地址系统操作说明

- 地址系统让地标风格、描述风格和独特地标关联在某个地理位置上：在报告生成中，只有地标和地标间、地标和描述间的距离足够近时才能接续叙述，以确保全篇合理且流畅。
- 地址也是一种“元风格”：风格组中不同风格的内容只要共享同一世界观，便可在同一张“地图”中计算地址，从而在叙述时形成超越单一风格的图样。

整个系统分三步走：

| 步骤 | 在哪里做 | 做什么                   |
|------|----------|-----------------------|
| 1. 申领 | GitHub Gist 仓库（网页编辑） | 声明“这个地址由我创建并负责”，写入注册表 |
| 2. 注册 | 程序内（文本管理器 / 地标对话框） | 把风格或地标绑定到已申领的地址       |
| 3. 生效 | 生成内容时 | 程序按配对与距离规则自动筛选地标、描述   |

**核心规则**：

- 申领在仓库中手工完成，程序内**不能**申领新地址；
- 程序内**注册**必须联网——每次点"确定"都会重新下载最新注册表，且只能
  注册其中已申领的地址。离线时可以查询本地缓存或清空注册的地址，但不能注册；
- 地址留空 = 未注册，到处可用，不参与任何地址规则。

在线注册表：<https://gist.github.com/j71408028-netizen/da0b6204e57a411462f2d72e3e0f1997>

## 操作规程

### 第 1 步：申领地址（在仓库中，需要新增地址时才做）

1. 打开上面的 Gist 链接，编辑其中的 `registry.json`（需发送请求）；
2. 按树形结构（`worlds` → `regions` → `regions` …）追加节点，每个节点写上
   `description`、`owner`、`claimed_at` 等申领信息（格式详见附录 B）；
3. 保存提交。之后在程序中点"刷新"即可看到新申领的地址。

### 第 2 步：为风格注册地址

适用对象：文本管理器中的**地标风格**和**描述风格**（两者都有"📍地址"按钮）。

1. 打开文本管理页，选中要操作的风格；
2. 选择地址，两种方式任选：
   - **级联选择**：从上到下依次选 世界观 → 一级地域 → 二级地域 → 三级地域，
     每级只列出注册表中已申领的选项；某级选"（不选此级，止于上一级）"表示
     地址到上一级为止；
   - **搜索**：在"序列化地址"输入框中输入，可按地址、描述、申领人过滤，
     点选结果后级联选择会自动联动。
3. 点"确定"保存。程序会联网下载最新注册表并校验该地址已申领，否则拒绝；
   若正在离线状态，会提示"离线，无法注册"。
4. 如需解除绑定，点"消除"再"确定"（无需联网）。消除后该风格不再参与地址规则。

⚠ **注意**：更改地标风格的注册地址后，原先基于旧地址组合出来的各地标地址
会失效（对话框中会给出警告），保存后请检查各地标的"地址(可选)"字段。

### 第 3 步：为独特地标填地址

在**地标编辑对话框**的"地址(可选)"中填写：

- **风格已注册地址时**：只填风格地址之下的剩余级别。例如风格注册到
  `TH-GSK1`，地标在东部 3 号单元，就填 `East-3`。
- **风格未注册地址时**：填写完整地址（含世界观和绝对规模），例如
  `1e4_2e3_2e2@TH-GSK1-East-3`。
- **双击地址框**：弹出下拉列表，列出注册表中该风格地址下的全部**已申领
  子地址**（含各级细度和描述），点选即回填。后台会联网刷新；离线时使用
  本地缓存。
  - 候选按地标尺寸自动过滤：最细单元边长小于地标尺寸的子地址会**置灰
    标记为"不推荐"**；若仍想使用，需手动输入地址。
  - 修改"尺寸(米)"会实时刷新候选的推荐状态。
- 地址留空 = 未注册，该地标到处可用。

### 生成时如何生效（自动，无需操作）

程序把风格注册地址与地标地址组合成地标的完整地址（组合规则见附录 A），
然后按以下规则筛选：

- **配对**：角色当前位置与地标地址同址或互相包含，且私有名约束互相满足，
  才能配对；世界观不同则完全不可达；
- **距离**：同址或包含 → 距离 0；否则取共同前缀之后首个分歧级，距离为
  双方在该级边长的平均值；
- **可达**：地标在角色 10 倍身高范围内才视为可达。

## 附录 A：地址格式与组合规则

### 地址格式

```
<绝对规模>@ [<私有名或*>!]<世界观>-<一级地域>-<二级地域>-<三级地域>
```

- **绝对规模**：以 `_` 分隔的 3 个数字，按 一级/二级/三级 给出该级单元的
  边长（米），如 `1e5_5e3_1e2` = 一级 100 km、二级 5 km、三级 100 m。
  包含地域段时必须提供；纯世界观地址可省略。
- **约束段**（`@` 与 `!` 之间，可省）：
  - 完全没有 `@...!` 段 → 不与任何带约束的地址匹配（仅用于无约束地址）；
  - `@!` 或 `@*!` → 不指定私有名（规模一致性由地址树保证）；
  - `@abc!` → 要求私有名恰为 `abc`。
- **世界观**：字母/数字/下划线，1~48 字符。
- **地域 id**：每级字母/数字/下划线，1~16 字符；最多三级（整个地址最多
  世界观 + 3 段）。

示例：`1e5_5e3_1e2@abc!ea1-1-2` = 一级 100 km、二级 5 km、三级 100 m，
私有名 `abc`，世界观 `ea1`，一级地域 `1`，二级地域 `2`。

### 风格注册地址与地标注册地址的组合

- **风格注册地址**：注册该风格所在的最上面若干级（世界观必填）。
- **地标注册地址**：补在风格注册级别之下 的剩余级别；风格未注册时填完整地址。
- **组合规则**：
  - 规模取"更细一方胜出"——地标带绝对规模时覆写风格的规模；
  - 私有名取先声明的一方（风格在前，地标覆写无效）；
  - 地域 id 取风格前缀 + 地标多余的后缀（公共前缀去重）。

## 附录 B：注册表 registry.json

### 树形式（推荐）

```json
{
  "version": 2,
  "worlds": {
    "TH": {
      "description": "东方Project", "owner": "紫", "claimed_at": "2026-09-05",
      "regions": {
        "GSK1": {
          "scale": ["1e4", "2e3", "5e2"],
          "description": "幻想乡腹地",
          "regions": {
            "East": {
              "description": "幻想乡东部区域",
              "regions": {
                "hrjj": {"scale": ["3e2"], "description": "博丽神社"}
              }
            }
          }
        }
      }
    }
  }
}
```

- 节点字段：`description` / `owner` / `claimed_at` 为申领信息；`scale` 为
  该级申领的规模数组（个数规则见下）；`chunk` 为可选私有名；`regions` 为
  下一级地域。世界观节点本身也是申领记录（可注册纯世界观地址，无规模）。
- **申领规模规则**：一级地域**必须**带 3 个规模；二级地域可选带 2 个
  （覆写该分支的二/三级边长）；三级地域可选带 1 个（覆写三级边长）；
  未覆写的级别沿路径继承上一级。因此同一分支内的规模一致性由树结构保证，
  不同分支允许不同规模。
- **私有名不参与覆写**：只取路径上最先声明的值，子地址的覆写无效。若某
  私有名的管理者希望在其他私有名的语境下继续添加，应申领一个平行地址。
- 不合法的节点（规模个数错误、id 不合法等）会被程序跳过，并在状态行提示。

### 旧扁平格式（兼容）

列表式：

```json
{"version": 1,
 "addresses": [{"address": "1e4_2e3_2e2@TH-GSK1-East-hrjj", "description": "博丽神社",
                "owner": "紫", "claimed_at": "2026-09-05"}]}
```

映射式：`{"1e4_2e3_2e2@TH-GSK1-East-hrjj": "博丽神社"}`。

### 命名规范（推荐）

- 世界观：大写字母缩写；
- 一级地域：大写字母缩写 + 数字；
- 二级地域：首字母大写完整词；
- 三级地域：小写字母缩写与数字。

同一地域下的直接子地域名称不应重名。

## 附录 C：配对与距离规则（详细）

- **配对**：只比较地域序列——同址或互相包含即可配对；规模一致性由地址树
  保证，不再要求三元组相等。私有名约束仍有效：一方声明了私有名时，另一方
  必须声明相同私有名。
- **距离**：同址或包含 → 0；否则取共同前缀之后**首个分歧级**，距离 = 双方
  在该级边长的平均值。
- 世界观不同 → 不可达。
- 在报告进行过程中，角色位置将不断更新为最后到达的最详细地址。新地标的地址与角色位置间的距离在一定范围内，才视为可达。
