# 角色演化全景

本文档汇总角色演化模型的完整设计：参与的量、每类行为的演化公式（与当前
代码一致）、以及模拟验证已确认的动态特性。各机制的代码入口见
`docs/world_pack_behaviors.md` 的行为钩子表；副本侧见 `docs/dungeon_chapters.md`。

## 1. 参与的量

| 层级 | 量 | 说明 | 存储位置 |
|---|---|---|---|
| 一阶 | 介入度 / 破坏性 | 坐标，统一边界 **0.5 ~ 4.5** | `CharacterSnapshot.evolution` 最后一行 |
| 二阶 | 介入度步长 / 破坏性步长 | 坐标的变化速率，随故事演化（二阶量） | `step_intrusion` / `step_destruction`（None 时回退性格初始步长） |
| 参数 | 敏感值 / 重力 | 性格常量，UI 范围 [-3, 3] | `Personality.sensitivity` / `gravity` |
| 参数 | 个性强度 | 性格常量，UI 范围 [0, 5] | `Personality.skip_base_prob` |
| 状态 | 行动点数 | 0~100（自然回复上限，返还可越上限） | `CharacterSnapshot.action_points` |
| 派生 | 策略值 | 见 §3，按行动点实时计算 | 不存储 |
| 累计 | 总伤亡 | 按 `compute_casualty(身高, 步进, 破坏性, 文本)` 随步进结算 | evolution 行 |

所有坐标操作（报告、副本、结局结算、负向演化）共用同一 0.5~4.5 夹取；
副本 `DungeonState` 与角色写回不再有独立边界，写回不越界。

## 2. 性格参数的分工

- **敏感值**：只直接操作**介入度**——报告/副本的介入度步长演化、地标切换、
  负向演化的介入度步进、章节敏感效果（属性为介入度时）。
- **重力**：对应地操作**破坏性**（同样的四类场景）。
- **策略值**（`Personality.strategy_value`）：
  `策略值 = 敏感值 × (1 - 归一行动点数) + 重力 × 归一个性强度`
  - 归一行动点数 = 行动点数 / 100（夹取 0~1），因子 `(1-归一行动点数)` 不小于 0，
    行动点未知时缺省 0.5；
  - 归一个性强度 = `skip_base_prob / 5`（夹取 0~1，即 `normalized_strength`）。
  - 用途：贪婪判定生成时的身高重映射（`CreationService.calculate_height`）、
    章节敏感效果作用于**非介入度/非破坏性属性**时（`chapters.sensitivity_amount`）。
  - 注意：负向演化的介入度步进由敏感值**直接**控制，不走策略值。
- **个性强度**：三处调制——步长恢复率 `0.2 × 强度`、每分钟行动点回复
  `1 + 0.3 × 强度`、不适应性衰减的强度 `1 - 归一强度`。

## 3. 演化机制与公式

### 3.1 报告步进（`StateService` + `context.py`）

每步步进权重 `步进`（由事件/探索决定）：

1. 坐标推进：`坐标 += 步长 × 步进`（夹取 0.5~4.5）
2. 演算坐标后扣除：`介入度步长 -= 步进 × 敏感值`；`破坏性步长 -= 步进 × 重力`
3. 步长向初始值恢复：`步长 += (初始步长 - 步长) × 0.2 × 个性强度`
4. 叠加不适应性衰减（见 §4）

以上 2~4 步由 `StateService.evolve_step_rates` 在坐标演化后一次完成
（先扣除再恢复）。

### 3.2 副本演化（`dungeon/rules.py evolve_attributes`）

与报告路径同构（三步相同，仅次序不同：副本侧先恢复步长再推进坐标）：
按 `(方向 + 敏感倍率修改) × 步长 × 段步进` 推进坐标 → 扣除 + 衰减。差异点：

- 段步进按文本类型固定（background 0.02 ~ action 0.3），方向由 AI 输出（±1）；
- 敏感倍率修改（`sensitivity_mods`）来自章节持续敏感效果与触发器限时效果，
  倍率 = `强度 × (性格值 + 客观影响)`（`chapters.sensitivity_amount`）；
- **交互选中不再直加坐标**：`is_interaction_chosen` 参数已废弃（仅兼容旧签名），
  交互对坐标的操作统一由绑定触发器跳转具有敏感效果的章节实现；
- 自定义属性不保存不跟踪，每次开副本重新计算。

### 3.3 地标切换（`apply_landmark_switch`）

- 切到 common：介入度 + 敏感值；切到 unique：介入度 - 敏感值；
- 破坏性 ≥ 3 时：切到 unique 破坏性 + 重力，切到 common 破坏性 - 重力。

### 3.4 闲置衰减 / 离线恢复（`decayed_coordinates` / `OfflineService`）

- 仅当坐标越过**性格初始值**（`init_intrusion` / `init_destruction`）时，
  向初始值回落 `fraction × 初始步长`，不越过初始值；方向由初始步长符号决定；
- 角色面板逗留每分钟 fraction=0.1；离线按分钟衰减，行动点按分钟回复
  `1 + 0.3 × 强度`（上限 100）；
- 离线伤亡按 `RhythmService` 作息调制因子（星期 × 2h 桶）结算，明细保留 72 小时。

### 3.5 负向演化（`apply_negative_evolution`，行动点 < 50 时每步自检）

- 介入度步进取 `-1 - 0.5 × 敏感值`（敏感值直接控制），
  破坏性步进取 `-1 - 0.5 × 重力`；
- 坐标按当前步长 × 上述步进平移（夹取 0.5~4.5），步长照常恢复/扣除并叠加衰减；
- 有变化时向演化表追加一行，行的步进取两种步进之和。

### 3.6 行动点经济

- 消耗：生成报告、进入副本（入口消耗由副本配置）、地址切换按距离；
- 回复：每分钟 `1 + 0.3 × 强度`（自然回复上限 100）；
- 返还：副本结局返还、报告解锁部位返还（无上限，仅不低于 0）。

## 4. 不适应性衰减（`decay_step_rates`）

**触发**：坐标达到 0.5 或 4.5 边界后（按当前坐标判断，报告/副本/负向演化
三条路径都传入坐标）。

**公式**：对应步长每步 `步长 ×= 0.4 ^ (|步进| × (1 - 归一个性强度))`。

- 几何收敛：贴边期间步长指数级趋向 0，防止二阶步长被反复踢升后发散；
- 个性越强衰减越弱（强度 5 时衰减为 0）——强性格「更不适应」，这是有意设计；
- 仅衰减，不负责敏感/重力的扣除；步进为负时取绝对值参与计算。

## 5. 已验证的动态特性（模拟结论）

以下结论来自 `developer_tools/evolution_sim.py` 的批量模拟（UI 参数范围内，
含参数角点；对比「长期点数不足」与「点数适中」两种消耗习惯）：

1. **步长平衡点**：无边界干涉时约为 `初始步长 - 步进 × 敏感值 / 恢复率`。
   敏感值符号决定长期漂移方向——正敏感 → 介入度步长下漂 → 坐标偏下；
   负敏感 → 上漂 → 坐标偏上。这是设计语义（敏感值直接操作介入度），
   不是退化；副本交互直加移除后，分布差异即由此单项决定。
2. **不适应性衰减有效**：贴边时步长几何收敛，配合 0.5~4.5 统一夹取，
   UI 参数范围内步长峰值实测 ≤ 10（此前策略值版本可到 27+），无步长发散、
   无 NaN/Inf。
3. **已知设计边界**：个性强度 5 时衰减为 0，全正角点在长期点数不足档
   （负向演化常态化）仍会贴 0.5 驻留——恢复率 1.0 每次把步长弹回初始值，
   随即被负向演化再踢一次；这是「强性格不适应衰减」的直接后果，若需消除
   可给强度 5 保留最小衰减率。
4. **点数适中档（负向演化触发率 <1%）**：无贴边死锁；步长在 0 附近存在
   有界极限环（恢复↔衰减↔扣除相互拉锯，幅度随参数 ≤ 几个步长单位），
   坐标正常游走，属正常动态。
5. **副本写回无越界**：坐标统一 0.5~4.5 后，副本结束时的角色坐标必然在
   角色边界内，不再出现 0~0.5 / 4.5~5 的驻留。

## 6. 模拟与验证工具

`developer_tools/evolution_sim.py`：对一组性格预设（UI 可设定范围内的角点
与典型值）持续模拟报告步进、地标切换、副本演化、闲置衰减、离线恢复、
负向演化，逐步记录坐标/步长/策略值/行动点，按口径（步长发散、步长坍缩、
坐标长期贴边、步长高频振荡、坐标静止、NaN/Inf）检测退化，
输出坐标跟踪图与 `report.md`。

```
python developer_tools/evolution_sim.py                  # 两种消耗习惯各 400 步
python developer_tools/evolution_sim.py --steps 2000     # 更长模拟
python developer_tools/evolution_sim.py --profile ap_moderate --only corner_pos
```

输出写入 `developer_tools/evolution_sim_output/<消耗习惯>/`（每角色四联
跟踪图 + 总览图 + 报告）。修改演化公式后建议跑一轮并对照 §5 检查。
