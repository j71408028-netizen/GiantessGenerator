# 副本角色系统：人物表、账本与人物视图

> **这一篇回答什么问题**：方案里怎么写「这个故事里有谁」（作者向），以及一局里
> 「谁在场、各自是谁、怎么不变」是怎么做到的——运行期角色账本（`dungeon/characters.py`）
> 的数据分层、身份状态机、在场观测、提示词投影、语音解析与两处界面。
> 字段声明的单一真相源仍是 `dungeon/schema.py`；本篇是字段与机制的权威说明，
> 与代码改其一要同步另一个。

## 1. 总览：设定与状态分开存

角色系统分四个平面（数据 / 提示词 / 语音 / 数值），共用一套身份、不共用存储：

| 角色 | 存在哪 | 说明 |
|---|---|---|
| 她 | 本局角色档案 | 名字 / 性格 / 身高 / 部位；跨方案复用 |
| 主角 | `protagonist_title` + `protagonist_background` | 唯一、视角固定，不进人物表 |
| 配角 | `cast[]` | `key` 有完整身份背景，`extra` 只有三条线索 |
| 环境 | 无实体 | 只是演化量的一个归属档（`owner`） |

**所有描述都是故事开始时的样子**，不是状态：谁死了、谁反目了不改配置，那是
`StorySummarizer` 的 facts。本局内的身份状态、当前称呼、特征与关系归运行期账本持有，
不回写配置。三条边界：

1. **她不在方案里**，主角不进 `cast[]`——否则「谁是主角」出现两处真相，渲染要开特例；
2. **在场以章节 `cast` 声明为主来源**，账本的观测结果只是补充，且不进「本段在场」声明行；
3. **账本只读投影，提示词构建不写账本**——所有写入走「回合提交」（§4）或后台抽取（§5）。

## 2. 方案字段（作者向）

### 2.1 主角

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `protagonist_title` | str | `""` | 称呼（说话人标记用），留空回退「主角」 |
| `protagonist_background` | text | `""` | 身份背景：他是谁、为什么在这儿、想要什么、怎么看她 |

`protagonist_background` 非空时，系统提示词的设定区（`initial_prompt` 之前）多一块：

```
【主角】指挥官
故事开始时：外地调来的救援调度员，任务是把东岸居民撤完；既指望她开路，又怕她失控。
（以上是起点不是现状，不必每段重述。）
```

它随系统提示词每段都在：主角是视角人物，「他是谁」与她的性格描述同级；每段变化的是
处境，走摘要 facts。也正因为它每段都在，文案必须点明是起点，否则 AI 会把它当成
每段都要维持的现状。

### 2.2 人物表（`cast[]`，`dungeon/cast.py`）

| 字段 | 类型 | 默认 | 哪档用 | 说明 |
|---|---|---|---|---|
| `id` | str | 同 `name` | 两档 | 标识；章节 `cast` 与别称解析都用它 |
| `role` | enum | `key` | — | `key` 重要角色（有完整背景）/ `extra` 群像 |
| `name` | str | — | 两档 | 称呼（必填）；**永远填真名 / 正式称呼**，也是说话人解析与音色匹配的最终键 |
| `intro_as` | str | `""` | `key` | 真名揭示前对外的**临时称呼**；空 = 开局即用 `name`。非空时开局处于 `temporary` 状态，渲染与说话人匹配优先用它，揭示后真名上场 |
| `pronoun` | enum | `""` | 两档 | `他` / `她` / 空；参与渲染与音色分池，空 = 不猜 |
| `voice` | str | `""` | 两档 | 显式音色；空 = 按 `pronoun` 落到音色池 |
| `background` | text | `""` | `key` | 完整描述 |
| `aliases` | list | `[]` | `key` | 别称：让 `@李队@` 与 `@李队长@` 归到同一人、同一把嗓子 |
| `call_her` | str | `""` | `key` | 他怎么称呼她 |
| `purpose` | str | `""` | `extra` | 作用：为什么要有这个角色 |
| `speech` | str | `""` | `extra` | 说话方式 |

两档**各只有一条「他是谁」的线索**，这是字段表按定位分家的理由：

- 重要角色只要 `background`。背景写清了，「说话是什么样」自然从人设里长出来；
  再给一栏 `speech`，作者会把同一件事写两遍，而 AI 拿到两份措辞不同的描述。
- 群像没有 `background`，才需要 `purpose`（他为什么在这个故事里）与 `speech`
  （他听起来什么样）两条线索。
- `aliases` / `call_her` 只属于重要角色：它们是喂给说话人解析与称呼渲染的**结构化线索**，
  而群像活得短、名字就是唯一标识，不值得再维护一套称呼。

`role_supports()`（`dungeon/cast.py`）是这条归属的代码落点，渲染与角色页都问它。

### 2.3 章节在场声明

```json
{ "name": "第三幕", "cast": ["李队长", "王店主"] }
```

章节用 `cast` 声明谁在场，写 id / 称呼 / 别称都认（`@` 会被剥掉）；
`chapters.normalize_chapter` 归一化：字符串按 `、,，;；空白` 切分、去 `@`、去重；
**没写就不补键**，旧磁盘内容一字不变。章节 `cast` 是**唯一**的在场来源。

### 2.4 校验要点

| 级别 | 条件 |
|---|---|
| error | 成员缺 `name`；`id` 重复；称呼 / 别称与另一个成员撞车；`intro_as` 与成员称呼 / 主角称呼撞车（都会让说话人与音色串台） |
| warning | `role` / `pronoun` 取值非法；章节 `cast` 指向不存在的成员；描述字段超长 |
| info | `key` 成员超过 6 个；`key` 没填 `background`（首次出场只会给出称呼） |

完整校验器口径见[数据模型 §9](script.md)。

## 3. 注入规则（提示词平面）

| 内容 | 位置 | 频率 |
|---|---|---|
| 主角设定 | 系统提示词设定区 | 每段（基底） |
| 本章在场行 | 用户提示词「当前地点」之后 | 章节 `cast` 非空时每段 |
| 配角设定块 | 同在用户提示词，紧跟在场行 | **首次出场一次** |
| 人物简报 | 首次出场块之后 | 已出场的在场成员**每段** |

**未在本章 `cast` 里声明的成员，一个字都不进提示词**——这同时解决了「AI 把每个人都
写进每一段」的问题，不在场的人根本不在提示词里。在场行与约束对 dialog / branch /
action / background 一视同仁。

首次出场时，填了线索的成员渲染成设定行；三条线索全空的成员给一条「由 AI 定」的指令：

```
【本段首次出场】赵司机
你需要在这一段让上述角色自然出场，并确定三件事：他们为什么在这个故事里、
各自的代词、各自的说话方式。确定之后保持前后一致。
（以上是起点不是现状，不必每段重述。）
```

AI 定的线索**不回写配置**：方案跨局复用，写回会让下一局顶着上一局的设定开场；
需要跨段保留的身份状态进本局账本（§4）。

首次出场之后，已出场的在场成员改走 `CharacterLedger.render_brief()`：重要角色给
身份首句 + 称她为 + 可变状态（特征 / 关系），群像给作用 + 说话方式。完整设定块会随
`messages` 窗口滑出，简报负责让「他是谁」不随窗口一起消失；简报只包含本章 `cast`
声明的在场者，不会把整张人物表每段重发。

**构建与提交分离**：`build_turn` 是纯构建（不写 `introduced_cast` / 账本 /
`_detail_queries`），这些副作用装进 `turn.effects`，由 `commit_turn` 在回合成功后提交；
预生成失败直接丢弃产物，不需要快照还原。写进 `messages` 的用户回合只保留章节 / 地点
与叙事指令（`canonical_user_entry`），在场行与简报由下一轮提示词重新渲染，不留在
历史里变成过期现状。

**说话人规则**（`coupling.py::SPEAKER_MARKER_RULE`，配置里有角色时才追加）：未知名
第一次说话用正文已出现的稳定临时称呼做标记、不要每段换叫法；真名揭示后一律用真名；
一个角色一段只有一个标记。空配置逐字不变。

## 4. 运行期账本（`dungeon/characters.py`）

### 4.1 三层字段

| 层 | 内容 | 归属 |
|---|---|---|
| `initial` | 方案成员的只读副本：id / name / 档位字段（含 `intro_as`） | key + extra |
| `mutable` | 身份状态：`status` / `handle` / `true_name` / `aka` / `traits` / `relation` | **仅 key** |
| `observed` | 在场观测：`presence` / `last_seen_step` / `last_seen_chapter` / `where` / `first_seen_step` / `voice_key` | key + extra |

群像（`extra`）只有初始字段：不积累特征、不参与身份揭示，简报每段按初始字段重新渲染。
AI 现编的角色（`source == "emergent"`）以 `key` 档登记，初始字段只有名字。

### 4.2 身份状态机

```
unknown ──首次被观测到（@说话人@ / AI 声明 / intro_as）──▶ temporary
temporary ──真名被揭示（正文锚点 / 手动确认）──▶ revealed
revealed ──不回退；改名只追加 aka──▶ revealed
```

- 没有 `intro_as` 的设定成员开局即 `revealed`（真名 = `name`），行为与旧版一致；
- 有 `intro_as` 的开局 `temporary`，对外称呼用 `intro_as`，真名等剧情揭示；
- `revealed` 后旧称呼进 `aka`（上限 6 个），说话人标记与语音都改跟真名。

### 4.3 在场观测

三个来源，优先级从高到低：

1. **声明在场**：章节 `cast`（`commit_turn` 里 `mark_declared`）→ 直接 `present`；
2. **说话人标记**：`@X@`（`observe_speaker`）→ 未知称呼登记 emergent；连续两段出现升级 `present`，否则 `mentioned`；
3. **正文点名**：已知角色的任一称呼出现在正文里（`note_mentions`）→ `mentioned`。

`decay(step)` 把两段以内没再出现的人标为 `absent`（保留 `last_seen` 供「最近离开」）。
观测只升级不降级：迟到的后台结果（step 更小）不回退；同一段里先被点名、又开口说话
升级为在场。**本章 `cast` 没声明的人即使 `present` 也不进「本段在场」行**，只在
「AI 现编且在场」的补充简报（`observed_brief`）里出现。

### 4.4 揭示与合并

- **自动合并最保守**：真名揭示（`_reveal_or_merge`）要求正文里同时出现旧称呼与真名
  两个锚点；AI 只给判断、正文找不到锚点的记进 `pending_merges`，不自动生效，
  等运行视图手动确认。
- **两个设定成员（`authored`）永不自动合并**：撞车时只登记 `pending_merges`。
- 合并 = 源并入目标：`aka` 并集、`traits` 并集（截断）、观测取较新、目标转 `revealed`；
  每次生效都写 `merge_log`（`origin` 区分手动 / 自动，上限 50 条），便于排查认错人。
- AI 抽取失败 / JSON 坏掉时账本不变，简报仍可用确定性字段渲染，不弹窗。

### 4.5 容量与快照

- 重要角色上限 24：满时先淘汰「非在场 + emergent」的最久未见者，设定成员永不淘汰；
- `traits` 每人 4 条 × 40 字，`aka` 6 个，单条简报总长 600 字（超限降级为名字一行）；
- `snapshot()` / `restore()`：整本账本（含 pending 与 merge_log）随回放落盘、回放头部
  整本还原为只读视图，保证人物档案与原局一致（旧回放没有快照，保持 seed 结果）；
- `revealed_snapshot()`：结局回顾用的已揭示重要角色快照（真名 + 别称 + 特征 + 关系），
  临时称呼与群像不进。

## 5. 状态从哪来（三条通道，AI 不是唯一来源）

| 通道 | 触发 | 落点 |
|---|---|---|
| 确定性 | `@X@` 解析、章节 `cast`、`intro_as`、说话人规则 | 不需要 AI |
| 细节探究搭车 | 后台细节调用返回 `characters[]`（`details.py::parse_character_updates`） | `apply_updates` |
| 摘要搭车 | 压缩响应带 `character_updates`（`summary.py::drain_character_updates`） | `apply_updates` |

两条 AI 通道都是**既有调用的搭车**，不新增调用次数；解析失败返回空列表，不影响主流程。
`apply_updates` 里：未知称呼首次出现登记成临时角色；真名揭示走 §4.4 的锚点规则；
特征 / 关系有界去重；群像不吸收任何可变状态。

## 6. 语音解析

`VoiceCaster`（`dungeon/audio/speech.py`）解析顺序：

1. 她的名字 / 昵称 → `voice_her`；
2. 主角称呼 → `voice_protagonist`；
3. **账本命中**（`resolve_character` 回调 → `voice_info`）：显式音色优先；没填就按
   代词过滤音色池后对**稳定哈希键**做 `crc32`；
4. 其余 → 全池 `crc32`。

关键在稳定哈希键（`voice_key`）：设定成员登记时就是真名，临时角色是第一个称呼——
临时称呼揭示成真名**不换嗓子**，同一角色的不同别名也稳定。性别分池只是内置表
过滤，不拆两个池；`pronoun` 为空就不过滤。`crc32` 不用 `hash()`（后者对字符串
随机化，重启进程全体换嗓子）。

方案级音色配置、合成与代理的说明见[副本对话语音](voice.md)。

## 7. 两处界面

| 态 | 位置 | 内容 |
|---|---|---|
| 作者态 | 方案编辑器「角色」页（`ui/scenario/character_page.py`） | 她 / 主角 / 人物表卡片 + 音色 + 演化量归属；`key` 卡片有「临时称呼」（`intro_as`）一行 |
| 运行态 | 副本窗口「人物档案」覆盖层（`dungeon/window/overlay.py`，C 键 / 工具条） | 只读为主：在场 / 最近离开两档，展开看别名 / 特征 / 关系 / 首次出场；对 AI 认错人可**手动合并**（`merge(origin="manual")`） |

运行态不提供编辑设定入口——方案跨局复用，运行期改设定会污染下一局。
结局回顾（`dungeon/window/persistence.py`）把 `revealed_snapshot()` 写进结局索引，
回放路径只读快照，不触发抽取、不写账本。

## 8. 兼容红线与自检

1. **空配置零差异**：`cast: []` 且无主角背景时，系统 / 用户提示词逐字不变
   （`tests/check_cast.py` 第一组断言）；
2. **不回写配置**：账本的一切只随局销毁；缺省键读取时归一化，旧磁盘内容一字不变；
3. **旧响应兼容**：细节 / 摘要响应没有新键时行为不变；
4. **回放只读**：`is_replay` 路径拦截一切账本写入。

自检：`python tests/check_characters.py`（账本：seed / 状态机 / 合并 / 容量 / 简报 /
在场观测 / 快照还原）、`python tests/check_cast.py`（人物表与提示词：空配置零差异、
构建 / 提交分离、历史净化、字段归属与撞车校验）。两者都在 `tests/run_checks.py`
离线集合里。
