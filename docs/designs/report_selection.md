# 报告生成：地标 × 描述的选取与配对

> **这一篇回答什么问题**：一份报告是怎么从「角色当前位置 + 已选风格」里
> 挑出地标对比与描述事件的——谁跟谁配对、顺序由什么决定。读者：想知道
> 报告为何出现这些内容的玩家，以及想知道自己的地标 / 描述风格何时会被
> 触发的资源开发者。地址本身怎么表达（格式 / 注册 / 距离）见
> [address_system.md](address_system.md)。

## §1 选取链条：四步各管什么

| 步骤 | 在哪 | 管什么 |
|---|---|---|
| 1. 尺寸匹配 | `core/logic/quips.py::get_comparisons` | 按部位 × 地标的倍率挑候选，只管「合不合身」，完全不知道空间；姿态类标签（能躺着不站着 / 四处走走等）在这里生效 |
| 2. 选取仲裁 | `services/exploration/arbiter.py::SelectionArbiter` | 空间硬闸（可达 / 私有名 / 世界观 / 耐久）＋ 描述配对车道 ＋ 顺序调解（本文 §2 / §3） |
| 3. 描述选取 | `core/logic/quips.py::select_quip_with_budget` | 在仲裁给出的车道窗口内，按坐标邻域与步进预算选一条描述 |
| 4. 演化推进 | `services/exploration/report.py::ReportEngine` | 坐标 / 步长 / 伤亡演化、地标耐久扣减、位置写回 |

设计定位一句话：仲裁器是**配对的裁决者，不是指挥官**——只有配对资格
（车道）与近匹配提拔是裁定；顺序权重都只是建议，尺寸匹配始终主导。

## §2 描述配对：车道

每个入选地标（槽位）× 每个已选描述风格，按风格的注册地址判定一条车道：

| 车道 | 判定 | 权重 |
|---|---|---|
| exact | 注册地址与地标地址**同址** | 1.0 |
| cover | 注册地址**覆盖**地标地址（风格注册得更粗） | 0.8 |
| free | 风格未注册地址，或地标本身无地址 | 0.5 |
| （无） | 不覆盖、世界观不同、私有名冲突 | 不参与该地标 |

资源作者需要知道的要点：

- **注册得粗 = 覆盖面广但权重低**：注册到世界观级可以给该世界所有地标
  写描述，但同址注册的风格在该地标前更优先；
- **无地址地标对全部风格开放**（free 车道），均值地标不注册地址也能
  获得描述；
- **描述池只被消费、不被剪枝**：选一条少一条，但前一个地标的窄覆盖
  不会删掉后面地标的可用风格（旧版本会，这是行为修复）；
- **池耗尽的槽位降级为纯地标对比**（「尺寸通过远程测量取得，尚未收集
  到事件记录。」），不会中断整份报告。

## §3 顺序：什么决定谁先出现

默认（按匹配）模式下按综合分排序：**尺寸匹配为主**，乘上三层调制——

1. **覆盖收益**：车道内有可用描述的地标略微优先；
2. **角色空间档案**（`services/character/spatial.py`）：到访历史的区域
   权重（常去的区域优先、长期不去会衰减回中性）、手工活动区域命中、
   空间类标签先验（旅行 / 地理测量 → 偏爱有地址的内容；四处走走 /
   能躺着不站着 → 活动范围倾向）。姿态类标签不在这里；
3. **路径连贯**：离角色当前位置近的地标略微优先。

**近匹配提拔**：若最优匹配的地标没有任何可用描述（车道全空或池耗尽），
而尺寸差在容差带内（约 1.4 倍以内）的次优地标自带描述覆盖，次优会被
换到前面。每份报告的提拔次数有上限（对比数的一半）——**覆盖只破平局
与近局，不推翻尺寸匹配的主导地位**。

两条边界约定：

- 玩家在设置里选了**按尺寸排序**（升序 / 降序）时，报告顺序保持玩家
  的呈现选择，仲裁只保留活动区域前移与近匹配提拔；
- **旧档案**（无到访历史、无空间标签）所有档案权重中性，选取行为与
  从前一致。

**环境一致性软权重**：角色空间档案的环境轴（`spatial.py` 的
`EnvironmentProfile`，把在线报告沉淀的环境证据按地址聚合）为每个带
地址的槽位给出环境估计（零证据为 `None`）。描述选取时对每条候选文本
单次采样环境因子，与槽位估计偏差越小排序加分越高（`quips.py` 的
`W_ENV_CONSISTENCY`）——角色更倾向讲述与所在环境相称的故事。三条
铁律：**零证据零权重**（无沉淀时不制造伪偏差，行为与从前一致）；
**软权重不做硬闸**（全池矛盾时矛盾文本照常被选，池耗尽降级不受影响）；
**环境只影响文本选取**，不进地标可达 / 配对的几何口径。行为包覆盖
选取且未支持 `env_estimate` 参数时软权重中性缺席（同车道兼容判定）。

**环境偏好（第三轴交点）**：`EnvPreferenceProfile` 从 step>0 的沉淀行
学角色偏好什么环境（值域等宽分箱直方图 + EWMA 淡出），TAG 先验
（`TAG_ENV_PRIORS` 并列表，旅行 / 地理测量偏爱人烟稀少）以伪计数做
初值，并受成熟度阻尼压低权重——step 正负是相关性不是因果。消费在
仲裁联合分：带地址槽位按其环境估计（零证据回落精确度默认值）查偏好
分布乘调制因子，角色常讲的环境里的地标略微优先。中性档案（无证据、
无先验标签）恒为 1.0，行为与从前一致。

## §4 覆盖报告与行为包兼容

- 每份报告携带 `coverage`（星槽数 / 浪费风格 / 实际触发的风格）与
  `promotions`（提拔记录：谁让位给谁），供后续界面展示与调试——目前
  只作为数据，未上界面；
- 行为包若覆盖了描述选取（`logic.select_quip_with_budget`）且未支持
  车道参数（`lanes`），程序自动退回旧的「按地标筛风格」模式——该包
  钉住它发布时的旧语义。

## 附录 B：参数

全部在 `services/exploration/arbiter.py` 顶部常量：`LANE_WEIGHTS`、
`NEAR_MATCH_TAU`（近匹配容差，log 尺度）、提拔上限（`limit // 2`）、
`W_COVER` / `W_REGION` / `W_PATH`（联合分权重）。环境两轴的常量在
各自实现处：`quips.py` 的 `W_ENV_CONSISTENCY`（一致性加分），
`spatial.py` 的 `TAG_ENV_PRIORS` / `_ENV_PRIOR_K` /
`_ENV_PREFERENCE_SMOOTHING`（偏好先验与阻尼）。默认值是建议值，
行为锁只锁语义不锁数值——调整后跑上述测试确认语义未破即可。

## 附录 C：开放点

- 近匹配容差与提拔上限需试玩校准（验收场景：最优匹配无覆盖时，次优
  是否如愿上移、报告是否仍以合身内容为主）；
- 可达范围（10 倍身高）目前是硬闸；是否降级为随距离衰减的权重未裁决；
- 副本侧的配对（方案阶段地址 / 出口回写 / 提示词注入地址上下文）与
  「从 A 移动到 B」的移动叙述保留待做。
