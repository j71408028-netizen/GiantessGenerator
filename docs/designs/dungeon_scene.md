# 副本内的地点与参照物

> **这一篇回答什么问题**：副本里"这是哪儿"要不要用地址？地址用在哪几处、怎么用？
> 尺寸换算句的参照物从哪来？读者：改副本提示词 / 结算 / 编辑器的人，以及写方案的
> 作者。

相关：[报告生成](report_selection.md)（主世界怎么用位置与地标）、
[地址匹配](address-system/matching.md)（`relate` 的空间关系与私有名）、
[数据模型](../Dungeon/script.md)（章节与方案的字段索引）。

## §1 地址是声明，不是推断

副本里没有移动、没有寻路，也没有"从 A 走到 B"的移动叙述：这一章发生在哪儿，是
作者写死的。所以地址在副本里不承担**求解**职责，只承担**声明**职责。

各用途建立在"作者把地点写死"之上：

| 用途 | 读什么 | 不声明时 |
|---|---|---|
| 展示 | 章节 `place` / `address` → 提示词一行（§7） | 什么都不显示 |
| 参照物 | 章节 `scene_landmarks` + `common_private_name`（§4） | 空池，不产生换算句 |
| 传送 | 结束章节 `exit_address` 写回角色 `position`（§8） | 位置不变 |

一条硬推论：**参照物是逐章可选的增强**。什么都没配的章节没有候选池，不产生换算句
——不是回落到全局全量。

## §2 不要的：自动匹配

曾有两版方案把主世界的地标选取搬进副本：一版是整套坐标匹配（距离筛选、三级降级、
`dgn_*` 维度隔离），一版是按章节地址做空间相配（`relate` 判"这一带"）。它们解决的
是"她此刻在哪、哪些地标够得着"——副本里这两个问题都被作者回答了，再算一遍只会
引入新的失败模式：巨型尺度下"10 倍身高"恒真、章节是图而配置是列表、外部地标
把场景带偏。

现在保留的只有一条判据：**这个常见地标是不是作者点名的那个世界**——用地址约束段
里的私有名判断，不算米数，也不算空间关系。

## §3 字段

独特地标内联在章节里（编辑器像敏感效果一样逐行添加）：

```json
{
  "name": "第三章",
  "place": "黑塔脚下的集市",
  "address": "1e3_1e2_1e1@HD!RW-CN1-HD",
  "scene_landmarks": [
    {"name": "黑塔", "size": 468, "dimension": "vertical"},
    {"name": "护城河", "size": 40, "dimension": "horizontal",
     "horizontal_type": "length"}
  ],
  "common_private_name": "HD",
  "exit_address": "1e3_1e2_1e1@HD!RW-CN1-HD-9"
}
```

| 字段 | 位置 | 类型 | 默认 | 说明 |
|---|---|---|---|---|
| `name` | 地标 | str | 必填 | 直接进提示词 |
| `size` | 地标 | float | 必填 | 米；`vertical` 为高度，`horizontal` 为长度 / 宽度 |
| `dimension` | 地标 | str | `vertical` | `vertical` / `horizontal` |
| `horizontal_type` | 地标 | str | `length` | `horizontal` 时用（`length` / `width`） |
| `place` | 章节 | str | `""` | 展示名；提示词与窗口都用它 |
| `address` | 章节 | str | `""` | 取景地址（完整地址）：地点行与展示用，**不再筛地标** |
| `scene_landmarks` | 章节 | list | `[]` | 本章在场的独特地标（建议 ≤5），全部按独特地标换算 |
| `common_private_name` | 章节 | str | `""` | 常见地标过滤私有名；空 = 不使用常见地标 |
| `exit_address` | 章节 | str | `""` | 结局传送目的地（§8） |

`scene_landmarks` 缺省 `[]`、`common_private_name` 缺省空——什么都没配的章节没有
候选池。方案级 `scene_landmarks` 与章节级 `landmarks` 白名单**已退役**：读到即按
没写处理，校验器报 warning 提示迁移。
`normalize_chapter` / `normalize_scene_landmarks` 负责把写坏的形状（非数组、非对象、
类型不对）归一回默认值，运行期不因一条坏数据中断。

## §4 候选池：独特地标内联配置，常见地标按私有名过滤

两类地标两条路，数据通道互不相通：

- **独特地标 = 章节内联配置（强控制）**。一章节会在场的独特地标理应很少（≤5），
  由作者在章节 `scene_landmarks` 里写明名称与尺寸；写明了就视为与她在场，对比的
  触发途径见 §5。数值就地写，不引用全局清单——清单里删掉一条不会再牵连任何章节。
- **常见地标 = 私有名过滤，放开交给风格设置**。章节 `common_private_name` 填了
  私有名时，全局池里**完整地址带同一私有名**的常见地标进池（常见地标挂在世界下，
  声明私有名就等于声明了那个世界的常见参照物）；留空 = 不使用常见地标——私有名
  是常见地标的唯一通道，不是"进一步收窄"的可选项。

```
本章独特地标（章节 scene_landmarks）
  ∪ 私有名一致的常见地标（仅当 common_private_name 非空）
```

| 章节 `scene_landmarks` | `common_private_name` | 候选池 |
|---|---|---|
| 空 | 空 | 空池（不产生换算句，**不回落全量**） |
| 有 | 空 | 只有本章独特地标 |
| 空 | 有 | 只有私有名一致的常见地标 |
| 有 | 有 | 并集，同名以独特地标为准 |

**"私有名一致"的定义**：`parse_full(地标完整地址).chunk == common_private_name`。
私有名的字符规则与地址约束段一致（字母 / 数字 / 下划线，≤64 字）。

不做米数阈值，也不做空间相配：私有名就是作者点名世界的方式，一章要哪个世界的
常见参照物，填名字即可。"只这一格"之类的空间收窄在真实需求出现之前不引入。

**私有名填错 = 匹配不到**（池子空或缺参照物），校验器报 warning；它不是 error——
空池也是答案。

**旧通道退役**：章节 `address` 不再参与地标筛选（只剩地点行与展示）；方案级
`scene_landmarks` 与章节 `landmarks` 白名单读到即忽略。

## §5 选取：两条触发途径

```
本章候选池 → get_comparisons(order="match", limit=1)
  ├─ 有候选 → 换算句
  └─ 没有   → 不产生换算句（正文照常推进）
```

触发途径有两条，独特地标两条都通：

1. **身体部位提及**（既有途径）：上一段正文出现部位词（`dungeon/prompts.py` 的
   `_PART_TRIGGER_PATTERNS`）时，按 `order="match"` 从本章池子取最接近的对比；
2. **同时在场**（独特地标独有）：内部判定原则——最近一或两个显示段落内，她的名字
   （或"她"）与独特地标的名字同段出现，或分处相邻两段，即视为"她与该地标同时在
   场"，下一轮提示给出该地标的身高对比。这是判定原则，不是提示词措辞：进提示词的
   只有对比句本身（"她的身高 X，约等于黑塔高度的 1.02 倍"），比例超出
   `get_comparisons` 可比范围、或上一轮刚提示过同一地标时不重复。

其余规则：

- 不返回 tier，也没有任何"能否继续"的判断读它——推进由章节与触发器决定；
- 名字命中全局屏蔽词（`blocked_words`）的条目按现状跳过；
- 体位筛选（`vertical` / `horizontal`）沿用 `get_comparisons` 既有规则；
- 候选池按章节名缓存，切章失效（身高变化不影响池子）；
- **空池就是空池**：作者把参照物配空时，不产生换算句，也不回退全量。

换算句还有第三个固定去处：文本校准块的「尺度」行（`dungeon/prompts.py`
的 `_calibration_block`）。校准块每轮给出当前坐标、介入度 / 破坏性谓词
（`core/scale_reference.py` 的谓词层，只保留客观状态、不含描写口径与视角）
与尺度上限；尺度行复用 `_get_height_match()` 的换算句，没有换算句时只写
身高，绝不从别处补场景词。深浅只由坐标决定，与 `direction` 的符号无关
（系统提示词里另有澄清句）。

## §6 全局池怎么进子进程

副本会话在独立子进程里跑，那里**没有地标仓库，也没有风格注册表**：`Landmark.address`
只是相对后缀，子进程解析不出完整地址——而私有名就藏在完整地址的约束段里。所以
地址必须在父进程解析好再进载荷：

- 启动前把 `merged_landmarks` 换成"每条带完整地址"的纯数据（`address` = 组合后的
  完整地址，`address_mode="exact"`），走 `dungeon/window/launch_payload.py` 的
  序列化 / 还原；
- 解析复用主世界那套 `AddressPlanner`（`services/exploration/address_plan.py` 的
  `landmarks_for_export()`），不新写一份组合规则；
- **缺省 portable 的常见地标升级为按风格注册地址参与**（`_common_style_address`）：
  常见地标挂在世界下，私有名随风格注册地址一起进完整地址，章节按私有名过滤才有
  东西可筛。显式声明过 `address_mode` / `address` 的按原样解析，独特地标不受影响；
- 解析失败的地标**照样进载荷**（名字、尺寸不变，只是标成 `portable`，不参与私有名
  过滤），不能因为一条坏地址让整个地标消失。

顺带说明"运行期不查仓库"不是纪律问题：子进程里根本没有仓库可查。

## §7 展示

- `dungeon/scene.py::place_label(chapter)`：`place` 优先，否则 `format_addr_compact(address)`
  的紧凑描述；两者都空则返回空串。作者起的名字总压过地址原文，写了 `place` 的章节
  不会把带精度说明的地址串漏到界面上。
- 提示词：`build_user_prompt` 在 `当前章节：…` 之后按需追加一行 `当前地点：…`
  （仅在非空时；虚构章节不写地址，这一行就不出现）。
- 会话访问器 `DungeonWindowBase.current_place()` 包的是同一个函数，留给窗口组件用；
  目前只有提示词在读地点，窗口侧尚无组件消费它。

**把地址写进提示词是有意的**：写实副本要的就是"她在一座真城市里"，模型知道地名
才会写出相称的街景；虚构副本根本不写地址，也就没有东西可漏。

## §8 结局传送

`exit_address` 决定"她出来后站在哪"，是副本改写主世界位置**唯一**的入口。

| 情形 | 行为 |
|---|---|
| 结束章节 | `DungeonStoryEngine._terminate_from_ending_chapter` 组装结算字段时带上 `chapter.exit_address` |
| 结算 | `scene.landing_position()` 能 `parse_full` 才算数：`char.position = exit_address`，并让那条演化行带 `position`（空间档案据此学到访） |
| 本局尚未创建角色 | 暂存到 `_pending_exit_position`，`_create_character_from_session` 建角色时作为初始 `position` 写入，用后清空 |
| 字段为空 / 解析失败 | 位置不变（**默认**，绝大多数结局） |

传送只有"结束章节"这一个入口：旧版 `ending` 触发器动作已退场（运行时跳过，见
`docs/Dungeon/script.md` §3.2），所以 `action_data` 里没有 `exit_address` 这条路径，
校验器也只检查章节字段。

允许跨维度：传送本来就是跨空间的事，不加"必须与入口同址"的限制。

进门仍是"门是门"，不改位置：角色有地址时只按入口地址（`entry_address`）算距离做
准入判定，判定通过后位置不动。

## §9 校验（`dungeon/validate.py`）

| 问题 | 级别 |
|---|---|
| 章节独特地标 `size` 非数 / ≤ 0 | error |
| `dimension` 非法 | error |
| 本章内重名 | error |
| 名字含换行或超过 40 字（直进提示词） | error |
| 章节 `address` / `exit_address` 无法解析 | error |
| `common_private_name` 含非法字符 / 超 64 字 | warning（常见地标会匹配不到） |
| 章节 `scene_landmarks` 不是数组 | warning（按空清单处理） |
| `horizontal_type` 取值非法 | warning（回落默认） |
| 本章只有一种 `dimension` | warning |
| 章节独特地标超过 5 条 | warning（建议 ≤5） |
| 方案级 `scene_landmarks` / 章节 `landmarks`（已退役字段） | warning（提示迁移） |
| 章节 `address` 与入口地址跨维度 / 跨一级地域 | warning（只提示，不拦截） |

编辑器在存盘前拦一遍写坏的条目（`ui/scenario/chapter_dlg.py`：名称缺失 / 重复 /
尺寸非正数当场弹窗），道理是运行期遇到坏条目只会静默跳过，不如当场说清。

## §10 验收（`tests/check_dungeon_scene.py`）

1. **空配置**：章节没配独特地标、也没填私有名 → 空池，不产生换算句，**不回落全量**；
2. **私有名过滤**：完整地址私有名一致的常见地标进池（含导出侧按风格注册地址升级的
   缺省 portable 条目）；不一致 / 没填私有名 / 独特地标不进；
3. **并集与同名**：两者都配时取并集，同名以独特地标为准；
4. **坏条目**：写坏的一条被跳过（校验 error），不拖垮其余条目；
5. **影响不到推进**：改清单 / 改私有名不改变可达章节与结局集合；
6. **会话访问器与提示词**：`chapter_landmarks()` 按章节缓存、切章失效；换算句取自
   本章池子；空池不产生换算句；
7. **载荷里的完整地址**：父进程解析 → JSON 往返 → 子进程仍能按私有名过滤；
8. **展示**：`place` / 紧凑地址 / 空三种形态，地点行紧跟章节行，虚构章节不出现；
9. **结局传送**：写回 `position` 并留带 `position` 的演化行；坏地址不动；未建角色
   时暂存且只消费一次；
10. **同时在场触发**：她的名字与章节独特地标的名字同段或分处相邻两段 → 下一轮提示
    出现该地标的身高对比；只有地标名没有她 / 相隔超过两段 / 上一轮刚提示过同一
    地标 → 不出现；身体部位途径不受影响。

第 5 条说明"候选池随玩家世界而变"是可接受的——它只影响措辞，不影响这局会走到哪里。
