# 地址匹配：格式、组合与距离

> 所属机制：[地址系统操作说明](README.md)。注册操作见该页「操作规程」。

## 地址格式

```
<绝对规模>@ [<私有名或*>!]<维度>-<一级地域>-<二级地域>-<三级地域>
```

- **绝对规模**：以 `_` 分隔的 3 个数字，按 一级/二级/三级 给出该级单元的
  边长（米），如 `1e5_5e3_1e2` = 一级 100 km、二级 5 km、三级 100 m。
  包含地域段时必须提供；纯维度地址可省略。
- **约束段**（`@` 与 `!` 之间，可省）：
  - 完全没有 `@...!` 段 → 不与任何带约束的地址匹配（仅用于无约束地址）；
  - `@!` 或 `@*!` → 不指定私有名（规模一致性由地址树保证）；
  - `@abc!` → 要求私有名恰为 `abc`。
- **维度**：字母/数字/下划线，1~48 字符。
- **地域 id**：每级字母/数字/下划线，1~16 字符；最多三级（整个地址最多
  维度 + 3 段）。

示例：`1e5_5e3_1e2@abc!ea1-1-2` = 一级 100 km、二级 5 km、三级 100 m，
私有名 `abc`，维度 `ea1`，一级地域 `1`，二级地域 `2`。

## 风格注册地址与地标注册地址的组合

- **风格注册地址**：注册该风格所在的最上面若干级（维度必填）。
- **地标注册地址**：补在风格注册级别之下 的剩余级别；风格未注册时填完整地址。
- **组合规则**：
  - 规模取"更细一方胜出"——地标带绝对规模时覆写风格的规模；
  - 私有名取先声明的一方（风格在前，地标覆写无效）；双方都声明具体
    私有名且不同时，组合失败；
  - 地域 id 取风格前缀 + 地标多余的后缀（公共前缀去重）；
  - **不再“尽量拼接”**：维度不同、地标地址不在风格地址之内（分支分叉）、
    层级超过三级时都会报错，该地标不参与本次地址规划，并在规划结果里记录
    诊断；不会静默退化成“无地址、到处可用”。

## 配对与距离规则（详细）

- **判定入口**：配对 / 覆盖 / 距离 / 私有名约束由 ``core.address_model.relate``
  一次算清（``AddressRelation``：空间关系 kind、距离区间、chunk_ok）；生成端
  （地标可达、描述配对）与副本准入都从这里取口径，不再各自拼装规则。
- **配对**：只比较地域序列——同址或互相包含即可配对；规模一致性由地址树
  保证，不再要求三元组相等。私有名约束仍有效：一方声明了私有名时，另一方
  必须声明相同私有名。
- **距离**：同址 → 0；目标包含角色位置 → 0；角色位置包含目标 → 区间
  `[0, 角色位置最小单元边长]`；否则取共同前缀之后**首个分歧级**，距离 =
  双方在该级边长的平均值。
- 维度不同 → 不可达。
- 角色位置无法解析时，地址系统给出 `invalid_position`，不静默重新锚定；
  地标地址存在但无法与风格组合时，给出 `invalid_address`，不静默当作未注册。
- 在报告进行过程中，角色位置将不断更新为最后到达的最详细地址。新地标的地址与角色位置间的距离在一定范围内，才视为可达。
