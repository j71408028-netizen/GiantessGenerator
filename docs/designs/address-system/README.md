# 地址系统：让报告里的世界连成一片

> 面向玩家。想给地标 / 描述风格申领或注册地址，看 [authoring.md](authoring.md)。

地址系统给地标风格、描述风格和独特地标登记一个地理位置；地址按
「维度 → 一级 → 二级 → 三级地域」组织，同一维度下的内容共用一张地图。

报告生成时，程序只让距离足够近的地标和描述接续叙述。所以她走过的地方
会像在同一张地图上，而不是随机拼贴：近距离的地标先出现，远处的、对不上的
地址不会被硬塞进同一份报告。

## 你会看到什么

| 现象 | 背后发生了什么 |
|---|---|
| 报告里的地标按距离出现 | 角色当前位置与地标地址配对成功才可达 |
| 不同风格能拼进同一份报告 | 这些风格共享同一个维度，即同一张地图 |
| 描述只配到「覆盖」当前地点的风格 | 描述风格的注册地址必须覆盖地标地址才配对 |
| 某个地标仍出现，但标着「定位精度不足」 | 距离上界超过身高 10 倍，可能到得去也可能到不去 |
| 进副本时提示无法进入 | 方案声明了「方案地址 + 最大距离」，角色当前位置不满足 |

## 玩家需要做什么

- **通常什么都不用做。** 地址由资源作者申领、注册好之后自动生效。
- 如果你想自己调**独特地标**的地址：在地标编辑对话框的「地址(可选)」里填写；
  双击地址框可以浏览已申领的子地址并点选回填。
- 地址留空时：独特地标跟随所属风格的地址；均值地标不参与地址规则，到处可用。
- 副本准入由方案作者设置；进不去时，多半是角色当前所在的位置离方案地址太远。

## 离线时

- 查看、选择本地缓存里的地址不需要联网，已有地址也照常参与报告生成。
- 但程序内**注册 / 修改**地址必须联网：点「确定」时会重新下载最新注册表并校验。

## 安全性

地址只影响筛选与配对，不执行任何代码。申领信息（`owner`、`claimed_at` 等）
写入公开注册表，会把你在注册表中填写的署名公开。
