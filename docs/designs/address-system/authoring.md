# 地址系统作者指南

> 面向地标 / 描述风格作者与世界包维护者；玩家向说明见 [README.md](README.md)。

整个系统分三步走：

| 步骤 | 在哪里做 | 做什么                   |
|------|----------|-----------------------|
| 1. 申领 | GitHub Gist 仓库（网页编辑） | 声明“这个地址由我创建并负责”，写入注册表 |
| 2. 注册 | 程序内（文本管理器 / 地标对话框） | 把风格或地标绑定到已申领的地址       |
| 3. 生效 | 生成内容时 | 程序按配对与距离规则自动筛选地标、描述   |

**核心规则**：

- 申领在仓库中手工完成，程序内**不能**申领新地址；
- 程序内**注册**必须联网——每次点"确定"都会重新下载最新注册表，且只能
  注册其中已申领的地址。离线时可以查询本地缓存或清空注册的地址，但不能注册；
- 地址留空：独特地标视为继承所属风格的注册地址；均值地标视为未注册，
  到处可用、不参与任何地址规则。

在线注册表：<https://gist.github.com/j71408028-netizen/da0b6204e57a411462f2d72e3e0f1997>

地址格式与距离规则见 [matching.md](matching.md)，注册表格式见
[registry.md](registry.md)。

## 操作规程

### 第 1 步：申领地址（在仓库中，需要新增地址时才做）

1. 打开上面的 Gist 链接，编辑其中的 `registry.json`（需发送请求）；
2. 按树形结构（`worlds` → `regions` → `regions` …）追加节点，每个节点写上
   `description`、`owner`、`claimed_at` 等申领信息（格式详见 [registry.md](registry.md)）；
3. 保存提交。之后在程序中点"刷新"即可看到新申领的地址。

### 第 2 步：为风格注册地址

适用对象：文本管理器中的**地标风格**和**描述风格**（两者都有"📍地址"按钮）。

1. 打开文本管理页，选中要操作的风格；
2. 选择地址，两种方式任选：
   - **级联选择**：从上到下依次选 维度 → 一级地域 → 二级地域 → 三级地域，
     每级只列出注册表中已申领的选项；某级选"（不选此级，止于上一级）"表示
     地址到上一级为止；
   - **搜索**：在"序列化地址"输入框中输入，可按地址、描述、申领人过滤，
     点选结果后级联选择会自动联动。
3. 点"确定"保存。程序会联网下载最新注册表并校验该地址已申领，否则拒绝；
   若正在离线状态，会提示"离线，无法注册"。
4. 如需解除绑定，点"消除"再"确定"（无需联网）。消除后该风格不再参与地址规则。

⚠ **注意**：更改地标风格的注册地址后，原先基于旧地址组合出来的各地标地址
会失效（对话框中会给出警告），保存后请检查各地标的"地址(可选)"字段。

### 第 3 步：为独特地标填地址

在**地标编辑对话框**的"地址(可选)"中填写：

- **风格已注册地址时**：只填风格地址之下的剩余级别，可写一级 `East`
  或多级 `East-3`。例如风格注册到 `TH-GSK1`，地标在东部 3 号单元，
  就填 `East-3`。也接受完整地址 `1e4_2e3_2e2@TH-GSK1-East-3`
  （必须同维度且位于风格地址之内）。
- **风格未注册地址时**：填写完整地址（含维度和绝对规模），例如
  `1e4_2e3_2e2@TH-GSK1-East-3`。
- **双击地址框**：弹出下拉列表，列出注册表中该风格地址下的全部**已申领
  子地址**（含各级细度和描述），点选即回填。后台会联网刷新；离线时使用
  本地缓存。
  - 候选按地标尺寸自动过滤：最细单元边长小于地标尺寸的子地址会**置灰
    标记为"不推荐"**；若仍想使用，需手动输入地址。
  - 修改"尺寸(米)"会实时刷新候选的推荐状态。
- 地址留空：独特地标继承所属风格的注册地址；均值地标不参与地址规则。
  均值地标若填写了地址，则和独特地标一样参与筛选。

### 生成时如何生效（自动，无需操作）

程序把风格注册地址与地标地址组合成地标的完整地址（组合规则见 [matching.md](matching.md)），
然后按以下规则筛选：

- **配对**：角色当前位置与地标地址同址或互相包含，且私有名约束互相满足，
  才能配对；维度不同则完全不可达；
- **距离**：同址 → 0；目标包含角色位置 → 0；角色位置比目标粗 → 距离是
  `0` 到角色位置最小单元边长的区间；分歧级 → 双方在该级边长的平均值；
- **可达**：用距离区间下界判断是否可能到达；若上界超出 10 倍身高，该地标
  仍可能被选中，但会标记“定位精度不足”；
- **描述配对**：描述风格的注册地址必须**覆盖**地标地址（描述风格更粗或同址），
  而不是像地标之间那样反向包含也算配对。覆盖程度的分层（同址 > 覆盖 >
  未注册）及其在报告选取中的完整用法，见 [report_selection.md](../report_selection.md)。

### 进入副本时的地址准入

副本方案可以声明「入口地址 + 最大距离」（见 [数据模型](../../Dungeon/script.md) §11）。
角色有地址时，其当前位置与入口地址必须同维度，且距离区间的**上界**不超过
上限（位置越粗，上界越大；避免“同在一个大区域就免费进入”），否则无法进入；
角色没有地址时不参与地址准入。入口地址是主世界里的门，与副本内章节的取景地址
（[副本内地点与参照物](../dungeon_scene.md)）是两回事。
